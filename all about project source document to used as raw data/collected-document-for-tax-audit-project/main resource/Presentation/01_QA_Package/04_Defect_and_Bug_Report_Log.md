# ITAS Tax Audit System — Defect, Bug & Architectural Observation Log

This document records all actual software defects discovered, diagnosed, and resolved during QA analysis and integration testing, followed by open non-blocking observations.

---

## 1. Resolved Defects (Verified Fixed in Codebase)

| Defect ID | Module | Severity | Summary & Root Cause | Fix Applied & Verification | Status |
| :--- | :--- | :---: | :--- | :--- | :---: |
| **`DEF-001`** | Comprehensive Audit (`StepCompReconciliations.tsx`) | **Critical (P0)** | **Crash on Step 4 navigation (`TypeError: Cannot read properties of undefined (reading 'length')`)**: When navigating to Step 4 of Comprehensive Audit, `reconciliations` sub-arrays (`vatVsCit`, `payeVsPayroll`, `customsVsPurchases`, `whtVsExpenses`, `items`) could be `undefined` in partially saved case snapshots, triggering an uncaught React render error boundary crash. | Added defensive normalization and `Array.isArray(...)` guards across `StepCompReconciliations.tsx` and `ComprehensiveAuditWorkspace.tsx`. Verified zero crashes on Step 4 transition. | **RESOLVED & VERIFIED** |
| **`DEF-002`** | Joint Audit Workspace & CAAT (`App.jsx`, `StepJointCAAT.tsx`) | **High (P1)** | **Joint Audit cases routed to Comprehensive Audit workspace & lacked dedicated Inter-Agency CAAT Engine**: Joint Audit cases were sharing the Comprehensive workspace and lacked the 5-module inter-agency CAAT capabilities defined in `ITAS_Joint_Audit_System.md`. | Routed Joint Audit cases to dedicated `/ja-workspace` (`JointAuditExecutionWorkspace.tsx`) and implemented the 5-module `jaCaatEngine.ts` (`StepJointCAAT.tsx` & `JointCaatAnalysisPanel.jsx`). | **RESOLVED & VERIFIED** |
| **`DEF-003`** | Case Handoff & Ownership (`userResolver.js`) | **Critical (P0)** | **False `'Case Handoff Required'` lock screen for assigned Team Leaders (`Berhanu Bekele`)**: `2027-f87ab51a-FED-federal-lto2-0077` was assigned to `Berhanu Bekele`, but the frontend compared raw UUIDs against username/display-name strings without canonical alias resolution. | Implemented `matchesCaseTeamLeader` and `matchesCaseAuditor` in `userResolver.js` resolving UUIDs, role-prefixed usernames (`teamleader-federal-lto2-ja-1`), emails, and full names. | **RESOLVED & VERIFIED** |
| **`DEF-004`** | Authentication & Password Policy (`BackofficeSecurityService.java`, `Login.jsx`) | **High (P1)** | **Existing seeded users blocked or forced into disruptive flows on login**: Password policy validator needed real-time character-class feedback while allowing existing MOR users to log in seamlessly with default password `Mor@2026!` and change their password on demand. | Configured `BackofficeSecurityService` so all 95+ existing accounts authenticate seamlessly with `Mor@2026!` (`mustChangePassword=false` by default) while enforcing full complexity rules when changing passwords. | **RESOLVED & VERIFIED** |
| **`DEF-005`** | Quality Assurance DTO (`QaReportResponse.java`) | **Critical (P0)** | **Type mismatch on QA Report arrays (`String` vs `List<String>`)**: `QaReportEntity` stores `keyStrengths`, `systemicVulnerabilities`, and `mandatoryCorrectiveActions` as `TEXT`, while the React frontend calls `.map()` on them, risking a runtime `.map is not a function` crash. | Updated `QaReportResponse.java` and `QaReviewService.splitList()` to serialize those three fields as `List<String>`. Verified in `TC-QA-003` and `TC-QA-006`. | **RESOLVED & VERIFIED** |
| **`DEF-006`** | Quality Assurance API Client (`src/features/qa/services/api.ts`) | **High (P1)** | **Frontend QA service called `/qa/cases` instead of `/api/v1/backoffice/qa/cases` and remapped workflow action names**: Requests fell back to local storage instead of hitting `QaController`, and `ISSUE_DEFICIENCY_NOTICE` was mangled into `RETURN`. | Updated `src/features/qa/services/api.ts` to call `/api/v1/backoffice/qa/cases*`, attach `Bearer` JWT + `X-Actor-Id` headers, and pass canonical workflow actions directly. | **RESOLVED & VERIFIED** |
| **`DEF-007`** | Quality Assurance Underlying Dossier (`QaReviewService.java`) | **High (P1)** | **`GET /api/v1/backoffice/qa/cases/underlying/{auditCaseId}` returned HTTP 500 when underlying case was not `COMPREHENSIVE_AUDIT`**: `ComprehensiveAuditService.getCaseSnapshot()` throws `IllegalArgumentException("Case is not a Comprehensive Audit.")` when called for `DESK_AUDIT`, `ISSUE_AUDIT`, or `TRANSFER_PRICING` cases. | Added multi-audit-type dossier builder fallback in `QaReviewService.getUnderlyingAuditCaseDossier()` so QA Inspectors can inspect underlying dossiers for all 5 audit types (`TC-QA-007`). | **RESOLVED & VERIFIED** |

## 2. Open Non-Blocking Architectural Observations

| Observation ID | Module | Severity | Description | Recommendation |
| :--- | :--- | :---: | :--- | :--- |
| **`OBS-001`** | Global Exception Handling (`DeskAuditController`, `ComprehensiveAuditController`) | **Low (P3)** | Domain type-guard exceptions (e.g., passing a `COMPREHENSIVE_AUDIT` UUID to `/api/v1/backoffice/da/cases/{id}`) throw `IllegalArgumentException("Case is not a Desk Audit.")`, which the global exception handler maps to `HTTP 500 Internal Server Error` (RFC 7807 `problem+json`) instead of `HTTP 400 Bad Request` or `HTTP 422 Unprocessable Entity`. | Map `IllegalArgumentException` for audit-type mismatches to `HTTP 400` or `HTTP 422` in `@RestControllerAdvice`. |
| **`OBS-002`** | Frontend Bundle Size (`vite build`) | **Low (P3)** | Production bundle `dist/assets/index-wxM7wMZ2.js` is `3,063.00 kB` (`644.31 kB` gzipped), triggering Vite's `>500 kB` chunk size warning. | Introduce route-level `React.lazy()` dynamic imports for `/ca-workspace`, `/da-workspace`, `/ja-workspace`, and `/qa-officer`. |
| **`OBS-003`** | Lombok `@Builder.Default` Warnings | **Low (P3)** | Maven compiler outputs 10 warnings on `CommitteeCaseEntity`, `CommitteeSessionEntity`, `ResearchNoteEntity`, `AdvisoryVotingEntity`, and `HandoffRecordEntity` where default field initializers lack `@Builder.Default`. | Annotate initialized fields on `@Builder` entities with `@Builder.Default`. |
